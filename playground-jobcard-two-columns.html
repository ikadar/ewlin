JobCard — layout 2 colonnes

Gauche = qui (ref · client / description). Droite = quand (date départ / D.L. BAT / écart planning).
Hauteur de carte = nombre de contraintes visibles : 2 lignes par défaut, 3 seulement si BAT + buffer.

1. Comparaison directe (job normal, avec buffer)

Même job rendu dans les 2 layouts. Montre pourquoi l'actuel paraît 3 lignes et le proposé reste 2.
Actuel3 rangs empilés
Pourquoi ça paraît 3 lignes
  • Le buffer +1j est un rang à part, sous la description.
  • Donc dès qu'il y a un buffer (= la plupart des jobs), la carte fait 3 lignes.
Proposé2 colonnes
Pourquoi ça reste 2 lignes
  • Le buffer est posé sous la date, dans la colonne droite.
  • La droite fait 2 lignes, la gauche fait 2 lignes → la carte fait 2 lignes.
  • Hauteur estimée : ~34 px (contre ~50 px actuellement avec buffer).

Détails techniquesà valider
Points à arbitrer avant code
  • Taille d'icône : j'ai pris 11×11 px (le plus petit utilisé dans JobDetailsPanel). Le JobDetailsPanel utilise 13×13 pour Calendar et 11×11 pour CalendarCheck. Dans une carte compacte, 11 pour les 2 me semble plus cohérent.
  • Couleur d'icône : zinc-500 (#71717a) comme dans JobDetailsPanel.
  • Format de date : "jeu. 25" (jour court + n°). Confirme que c'est le format voulu, ou tu préfères "25/04" ?
  • Gap entre colonnes : 10 px testé. À resserrer à 8 px ou étirer à 12 px ?
  • Top-alignement des colonnes : la droite s'aligne au haut, le buffer se "pose" naturellement sous les dates même si la description gauche est plus haute.
  • Hover : on garde le même (bg-white/5 sur hover, bg-white/10 quand sélectionné).
  • Quand description wrappe : elle truncate toujours (1 ligne max). À confirmer.
