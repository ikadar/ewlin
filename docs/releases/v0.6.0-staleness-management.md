## Overview

Closes the "silent staleness" problem on the planning view: a schedule that no longer reflects the user's latest edits (deadline changes, operator absences, station maintenance, BAT status updates…) but looks fresh in the UI. Ships four interlocking pieces:

1. **Safety zone** — a rolling window (default 12 h from now) during which placed tiles are pinned by the scheduling engine. Prevents the recompute from rearranging cards currently in preparation/production.
2. **Two-phase compute** — Phase 1 `POST /compute-fast` (FBI + Moore only, < 1 s) renders the planning quickly. Phase 2 `/compute-lns/stream` runs LNS for up to 60 s in the background, auto-applies any improvement, and emits a Waze-style notification.
3. **Unified compute toaster** — single top-right stack (max 3 visible) for every compute signal: auto-recompute, manual Alt+P compute, background LNS optimisation. Five types, in-place update on the same id.
4. **Auto-recompute everywhere** — every mutation that changes the engine's view of the problem (job CRUD, operator absence/skills/schedule, station availability, station category rules, outsourced provider config, element status, scheduling constraints) triggers a debounced two-phase compute via RTK listener middleware.

## Scope

### In Scope

- Rolling safety zone with per-tile override widget (Sky snowflake) in both planning views (machine grid + operator grid)
- Two-phase compute pipeline in Rust engine: `/compute-fast` (FBI + Moore) and `/compute-lns/stream` (LNS only, seed + 60 s budget + cancel)
- Lexicographic LNS objective: primary = late_job_count, secondary = any-of-strict calage_bonus (sum/mean/median)
- Unified compute toaster: top-right, compact, 4 s auto-hide, 5 types (info/success/error/progress/waze), in-place update on same id
- Auto-recompute trigger via RTK middleware on a typed allow-list of 17 mutation endpoints
- StalenessBadge fallback for compute failures
- Admin Settings pages: Safety Zone (slider 0 → 168 h) + Scheduling Constraints (CRUD)
- Playwright E2E regression test

### Out of Scope

- ComputeModal rewrite — kept its rich progress UI, only emits a Waze toast on lnsDone
- Operator absence → SchedulingConstraint(OperatorAbsent) unification (both models coexist; cleanup in later release)
- Observability counters for LNS improved vs no-change
- SSE reconnection logic (mono-user assumption holds)

## Technical Notes

- **LNS objective** switched from `(late_job_count, weighted_lateness_minutes)` to `(late_job_count, calage_bonus_tuple)` with any-of-strict acceptance on (sum, mean, median). `engine::lns::is_strictly_better` is the single source of truth; 5 unit tests cover the compare rules.
- **Mono-user LNS** — the Rust engine keeps one global `AtomicBool` cancel token, so opening a new `/compute-lns/stream` supersedes the in-flight one. Acceptable under the mono-user Flux assumption.
- **Debounce singleton** — compute orchestration lives in `apps/web/src/hooks/autoRecomputeRuntime.ts` as a module-scope singleton. `useAutoRecompute` is a thin subscriber; the timer survives any React tree churn.
- **Type-safe allow-list** — `AutoRecomputeEndpointName` is built with `Extract<keyof typeof api.endpoints, ...>` per slice, so renaming an endpoint fails at compile time.
- **Diff-aware JCF save** — `JobService::elementsStructurallyEqual` signature compares (name, label, spec, prerequisite names, raw DSL). Identical payload → skip rebuild → pins + safety overrides survive.

## Release Notes Draft

```markdown
## v0.6.0 – Staleness management

**Release Date:** 2026-04-21

### Summary

The planning view is now reactive. Every edit that changes the scheduling
problem — from a JCF save to an operator's absence — triggers a two-phase
compute (fast first, LNS in background) and the cards stay fresh. Tiles
already in preparation are protected by a configurable safety zone so the
optimiser never reshuffles committed work.

### What's New

- Safety zone with per-tile override
- Two-phase compute (fast + 60 s background LNS with auto-apply)
- Unified top-right compute toaster, including Waze-style LNS improvement
  notifications
- Auto-recompute on 17 mutation endpoints via RTK middleware
- `/settings/safety-zone` and `/settings/scheduling-constraints` admin pages

### Bug Fixes

- JCF save no longer destroys task ids + pins + safety overrides when the
  elements payload is structurally unchanged (diff-aware rebuildElements).
- `handleJcfSave` returns to `/stations` when the modal was opened from
  there, avoiding an accidental unmount that could cancel the pending
  recompute.

### Breaking Changes

- None at the API level. `POST /api/v1/schedule/compute` now routes to
  `/compute-fast` on the engine (Phase 2 LNS runs asynchronously via the
  new SSE endpoint). Clients relying on the in-request LNS result must
  migrate to the SSE stream.

### Migration Guide

1. Pull and rebuild the Rust engine (`cargo build --release`).
2. Apply the DB migration: `php bin/console doctrine:migrations:migrate`.
3. Deploy the frontend.
```
