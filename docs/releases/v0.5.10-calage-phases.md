# v0.5.10 — Calage phases and folder tab

## Summary

Two related tile-rendering changes:

1. **Re-calage phases** from the scheduling engine are now surfaced on
   tiles. When a setup expires mid-run (post-peremption), the engine
   records the re-staging windows; the UI renders each as a dashed-red
   section mirroring the initial setup, so operators can see every calage
   cost for a given assignment.

2. A **hover-only folder tab** hosts the completion and pin controls.
   The tab protrudes above the tile as a colored flap integrated with
   the tile's border-left and state palette. Inline icons disappear
   from the tile body; the pin stays inline only while the tile is
   actually pinned (status), hidden otherwise.

Playground iteration:
`playground-tile-calage-phases.html`.

## Engine changes (`services/scheduling-engine`)

- `Action` gains `current_recalage_start: Option<u32>` and
  `recalage_segments: Vec<(u32, u32)>`.
- `apply_peremption_rule` takes the current tick and, in the post-setup
  regime, records the start. `advance_action_at_tick` closes the segment
  when `eat` climbs back to `setup_ticks` (re-setup done).
- `ComputedAssignment.recalages: Vec<PhaseSegment>` surfaces each closed
  segment as RFC 3339 `{start, end}` timestamps. Chunk merging
  concatenates across chunks.

## API surface

- `packages/types`: new `PhaseSegment` type + `TaskAssignment.recalages`.
- `services/php-api`: `TaskAssignment` value object gains `recalages`,
  preserved across `withX` mutators and `fromArray`/`jsonSerialize`
  round-trips. `ScheduleComputeController` forwards the field without
  transformation.

## Frontend changes (`apps/web`)

### Folder tab

- `.folder-tab` in `index.css`: positioned above the tile, solid bg
  pre-composed via `color-mix` to avoid alpha-stacking at the seam,
  border-left inherits the tile state color.
- `Tile.tsx`: folder tab markup with `tile-tab-complete` / `tile-tab-pin`
  buttons. Inline Circle / Pin moved under `.inline-check` /
  `.inline-pin` spans, toggled by CSS based on the tile's `data-pinned`
  attribute.
- `colorUtils.ts`: `getStateRgb` exposes `tile`, `border`, `text` RGB
  triplets; Tile.tsx sets them as CSS custom properties so dependent
  layers don't duplicate the palette.

### Calage phase dashed divider

- `[data-testid="tile-setup-section"]` and
  `[data-testid="tile-recalage-section"]` share a `1px dashed rgba(239,68,68,0.9)`
  bottom border (F variant). The re-calage section uses the same CSS
  rule, so initial setup and re-calage read visually identical — no
  special marker for the peremption event beyond the extra section.

### Recalage rendering

- `Tile.tsx` maps `assignment.recalages` to absolute-positioned divs
  with `data-testid="tile-recalage-section"` at each segment's time
  offset. Zero segments → no render.

## Tests

- Rust: 7 peremption unit tests in `forward_pass.rs::peremption_tests`.
- PHP: `TaskAssignment` round-trip tests already cover the DTO surface.
- Playwright: `apps/web/playwright/calage-phases.spec.ts` — folder tab
  hover, inline icon visibility rules, setup divider color, recalage

## Migration notes

- `TaskAssignment` value object now has an extra `recalages` field.
  Existing rows hydrate with `[]` via `fromArray` default; no DB
  migration needed.
- No breaking API change — `recalages` is `#[serde(default)]` Rust-side
  and optional in the TS type.
